# v2.1 — Single-Stock Alpha Factor Scoring

## Motivation

v2.0 delivered the S&P 500 screener (`stratgen screen`), which filters ~503 tickers to ~478 passing stocks. The next step is to compute a composite alpha score per stock by running all optimized time-series factors across the screened universe.

The v1.x pipeline produced 48 PASS/MARGINAL factors in `results_factors_opt.json`, each with cached `code` and `optimized_params`. The scoring pipeline reuses this cached code — no LLM calls needed at runtime.

## Design Decisions

### Mock Strategy extraction

The cached factor code uses `backtesting.py` Strategy classes. The alpha computation lives inside `alpha_func` closures in `init()`, called via `self.I(alpha_func, self.data.Close, ...)`. Params are class-level attributes.

Rather than running ~48 × 478 = ~23,000 full backtest simulations, we use a lightweight mock:

1. `exec()` the code string to get the `GeneratedStrategy` class
2. Create a `_MockStrategy` instance (does not inherit from `Strategy` to avoid its read-only `data` property)
3. Copy class-level params, override with `optimized_params`
4. Set `.data` to a `SimpleNamespace` with OHLCV numpy arrays
5. Set `.I()` to a mock that just calls `func(*args)` and captures the result
6. Call `init()` via the unbound method → capture alpha array

This avoids the overhead of backtesting.py's backtest loop while extracting the same alpha values.

### NaN-tolerant panels

The existing `build_panel()` uses `dropna()` which drops any row where ANY ticker has NaN. With ~478 tickers this would be too aggressive. The scorer builds panels with `pd.DataFrame({t: series for t, series in ...})` and tolerates per-ticker NaNs, only requiring a minimum of 10 non-NaN tickers per date for IC computation.

### IC-weighted combination

For each factor:
1. **Z-score cross-sectionally** — at each date, normalize factor values across tickers (subtract mean, divide by std)
2. **Compute rolling IC** — trailing Spearman rank correlation of factor values vs next-day returns, averaged over a 60-day window
3. **Weight = rolling IC** — the IC value itself serves as the weight, preserving sign (positive IC factors get positive weight, negative IC factors get negative weight)

Composite alpha = sum(z_score_i × IC_weight_i) / sum(|IC_weight_i|), normalized per date.

## New Modules

### `scorer.py` — Core scoring logic

Pure functions following the `screener.py` / `cross_section.py` pattern:

- `extract_factor_values(code, df, params)` → `pd.Series`: Mock Strategy extraction
- `compute_factor_panel(factor, universe_data)` → `pd.DataFrame`: One factor across all tickers
- `zscore_cross_sectional(panel)` → `pd.DataFrame`: Row-wise z-scoring
- `compute_rolling_ic(factor_panel, returns_panel, window)` → `pd.Series`: Rolling Spearman IC
- `composite_alpha(factor_panels, returns_panel, ic_window)` → `(pd.DataFrame, dict)`: IC-weighted combination

### `factor_score.py` — Score command runner

`run_score()` orchestrates the full pipeline:
1. Load screened tickers from `results_screen.json`
2. Load optimized factors from `results_factors_opt.json` (filter by verdict)
3. Download OHLCV for screened tickers (cached Parquet)
4. Compute factor panels (one per factor, dates × tickers)
5. Build returns panel from Close prices
6. `composite_alpha()` → composite scores
7. Rank stocks by latest composite score
8. Save to `results_score.json`

## CLI

```bash
python -m stratgen score [--universe sp500] [--ic-window 60] [--top-n N] [--min-verdict MARGINAL]
```

| Flag | Default | Description |
|------|---------|-------------|
| `--universe` | sp500 | Stock universe |
| `--ic-window` | 60 | Rolling IC window in trading days |
| `--top-n` | all | Use only top N factors |
| `--min-verdict` | MARGINAL | Minimum factor verdict (PASS or MARGINAL) |
