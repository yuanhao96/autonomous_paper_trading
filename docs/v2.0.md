# v2.0 — S&P 500 Universe + Stock Screener

## Motivation

v1.3 cross-sectional results on S&P 100: 17/18 FAIL, 1 MARGINAL (WQ-115, IC=-0.012). The universe was too small — 100 large-cap stocks are highly correlated, providing insufficient cross-sectional dispersion for rank-based alphas.

The v2.x series pivots to a **screen → score → allocate** pipeline:
1. **v2.0**: Expand to S&P 500 + quantitative screener
2. **v2.1**: Per-stock alpha scoring with IC-weighted factor combination
3. **v2.2**: Cross-sectional validation on the larger universe
4. **v2.3**: Portfolio construction with risk constraints
5. **v2.4**: Live paper trading loop via Alpaca

This document covers v2.0: the universe expansion and screener.

## Design Decisions

### Why S&P 500?

- ~500 stocks provides real cross-sectional dispersion
- All stocks are liquid enough for daily trading
- Data availability back to 2019 via yfinance
- Large enough for meaningful quintiles (~100 stocks per group)
- Well-known benchmark (SPY) for comparison

### Why screen?

Not all 500 stocks are equally tradeable or data-rich. Screening removes:
- Illiquid stocks (wide spreads, hard to enter/exit)
- Low-price stocks (higher transaction cost as % of price)
- Stocks with data gaps (corrupt backtest results)

Screening is **not** alpha — it's hygiene. The factors do the stock-picking.

### Screener criteria

| Filter | Threshold | Rationale |
|--------|-----------|-----------|
| Average daily volume (ADV) | > $5M (20-day avg of close × volume) | Ensures tradeable liquidity |
| Price floor | > $10 | Avoids penny-stock-like behavior in large-caps |
| Data completeness | > 95% of trading days have data | Prevents NaN-corrupted factor computations |
| Minimum history | ≥ 2 years of data | Enough for rolling factor windows + train/test |

Expected output: ~350-450 stocks from the 500 (some will fail data download or liquidity thresholds).

```python
    ticker: str
    passed: bool
    adv_20d: float        # 20-day average dollar volume
    last_price: float     # Most recent close
    data_completeness: float  # Fraction of expected trading days with data
    sector: str | None    # GICS sector (from yfinance .info if available)
    fail_reasons: list[str]

def screen_universe(
    universe_data: dict[str, pd.DataFrame],

    min_history_days: int = 504,  # ~2 years
) -> tuple[list[str], list[ScreenResult]]:
    """Filter universe by liquidity, price, and data quality.

    Returns (passing_tickers, all_results).
    """
```

## Data Considerations

### Download time

~500 tickers × yfinance download ≈ 10-15 minutes on first run (cached afterward). The existing `download_universe()` function handles this with Parquet caching.

### Storage

~500 Parquet files × ~1500 trading days × 5 OHLCV columns ≈ 50-100 MB in `data/`.

### Rate limiting

yfinance has informal rate limits. The existing `download_universe()` already handles this gracefully (individual failures skip with a warning).
